# Stop, storage and recovery review — 2026-11-27

Reviewed the open and closed GitHub ticket index, discussions and the updated [PR #69](https://github.com/Alos21750/UAV-Downloader/pull/69) at `d2ed712`. This release incorporates its standalone `7403bc8` commit with attribution, **not the remaining provider, Watcher or queue changes**. Its updated gateway-body and generic error-grid regression cases passed in a focused run (113 tests). Those are parser checks, not proof of live media availability.

## Reproduced defects and fixes

- On both v3.8.4 and the revised PR, a user stop during executor submission could report “cannot schedule new futures after shutdown” instead of a normal stop or a concurrent disk error. A real-thread regression gates submission and an in-flight writer using events, not sleeps. The new code distinguishes submission from worker exceptions, waits for active writers, preserves the actual disk error, and releases the pool reference on failure. This is not a general cleanup/retry ownership fix for [#68](https://github.com/Alos21750/UAV-Downloader/pull/68).
- NAS queue restart used to discard the storage stop reason. If shutdown coincided with that error it also mislabeled the job as interrupted. A persisted failure now survives both transitions; the next job stays pending until explicit resume. Only the known program-generated reason is restored; arbitrary old logs are not displayed. If the state file itself cannot be written, a restart cannot recover information never saved.

## Issue history vs. what the code proves

The first frozen candidate was rejected: a saved disk-full job actually showed the generic page/parse hint. Browser now identifies the program's own serialized storage error before matching keywords in the path, repairs stale codes on restore, and gives instructions in all five languages. An unrelated clipboard URL also appeared in the first candidate's input field. Passive suggestions are now limited to supported plain links and never replace manual text; explicit paste/import remain available.

- [#54](https://github.com/Alos21750/UAV-Downloader/issues/54) and [#57](https://github.com/Alos21750/UAV-Downloader/issues/57): the fixes protect a client-side stop/error path. They do not establish why a drive went offline or a destination vanished.
- [#71](https://github.com/Alos21750/UAV-Downloader/issues/71), [#72](https://github.com/Alos21750/UAV-Downloader/issues/72), [#73](https://github.com/Alos21750/UAV-Downloader/issues/73): Browser already retains a verified MissAV prefix for manual export. Existing cached files are not automatically trusted as new receipts. Expanding a receipt across retries would need a robust source/playlist identity, not just an equal segment count and output path. A separate export currently needs temporary space for both TS and MP4. None of these properties explain a remote 403.
- Watcher already separates subtitle work from downloading; an additional queue redesign based on old reports is not justified. NAS serial job execution is intentional and separate from per-video segment concurrency. [#55](https://github.com/Alos21750/UAV-Downloader/issues/55) remains a request for an embedded player, not just the existing external preview. [#59](https://github.com/Alos21750/UAV-Downloader/issues/59) and [#62](https://github.com/Alos21750/UAV-Downloader/issues/62) remain separate connection and startup investigations. No provider bypass, UI rewrite, or hardware diagnosis is part of this release.
